# Сигналы SmartSpectra в плагинах

Раньше плагин получал только готовые жесты (`nod`, `smile`, …). Теперь он может читать сами измерения SmartSpectra и
задавать условия сам: сколько раз моргнул, куда повернул голову, какой пульс.

Контракт лежит в `packages/protocol/src/signals.ts` (типы), `server-link.ts` (сообщения сервера) и `plugin.ts`
(заголовок плагина). Жесты остаются как есть, сигналы их не заменяют.

## Сигналы

| Сигнал       | Значение                                         | Откуда в SDK                              | Когда приходит                               |
| ------------ | ------------------------------------------------ | ----------------------------------------- | -------------------------------------------- |
| `blink`      | `{ detected }`                                   | `face.blinking`                           | только при смене значения (фронт = моргание) |
| `pose`       | `{ yaw, pitch }` от позы покоя, в долях глаз     | считается сервером по `face.landmarks`    | до 15 раз в секунду                          |
| `expression` | оценки 0–100 по 8 выражениям                     | `face.expression`                         | не чаще раза в 100 мс                        |
| `pulse`      | `{ bpm, confidence, stable }`                    | `cardio.pulse.rate`                       | с каждым новым значением SDK                 |
| `breathing`  | `{ rate, confidence, stable }`                   | `breathing.rate`                          | с каждым новым значением SDK                 |

Время `at` у `blink`, `pulse` и `breathing` берётся из timestamp SDK, у `pose` и `expression` это время сервера.
`stable` у `pulse` в SDK означает confidence не ниже 40, у `breathing` не ниже 45.

`blink` пока не проверен на реальных морганиях (в живом тесте Glimra `blinking` не дал ни одного). Пульс и дыхание
не медицинские показания: SDK считает их по видео, плагин не должен ставить диагнозы или давать советы по здоровью.
Точки лица (`landmarks`) плагинам не отдаются.

## Путь данных

1. Плагин объявляет сигналы в заголовке: `// @signals blink, pose, pulse`. Окно установки показывает их списком, как
   сейчас показывает `@gestures`. Без заголовка плагин сигналов не получает.
2. Расширение при старте сессии передаёт серверу объединение сигналов плагинов страницы: `start.signals`.
3. Сервер измеряет и шлёт только запрошенное: `{ type: "signal", sample }`. `pulse` и `breathing` добавляют в сессию
   метрики SDK `cardio` и `breathing`, поэтому без них они не запрашиваются (лишняя нагрузка и задержка). Набор сигналов
   меняется только перезапуском сессии.
4. Расширение доставляет отсчёты на страницу событием `SIGNAL_EVENT_NAME` (`pleiades:signal`) на `window`, как жесты.
5. Рантайм `@repo/reactions` складывает отсчёты в скользящую историю и отдаёт плагину.

Сигналы идут только пока работает камера (`@camera always`, как для `onGesture`), ничего не сохраняется на диск.

## API плагина

```js
// ==Reaction==
// @name     Blink counter
// @match    *://*/*
// @camera   always
// @signals  blink, pose
// ==/Reaction==

reaction("blinks")
  // триггер на каждый отсчёт сигнала
  .onSignal("blink", (ctx) => {
    if (ctx.signals.blinks(2000) >= 2) ctx.toast("Two blinks");
  })
  .onSignal("pose", ({ sample }) => {
    if (sample.value.yaw > 0.3) console.log("looking right");
  });
```

`ctx.signals` доступен в любом обработчике (не только в `onSignal`):

| Член                                      | Что возвращает                                                                                  |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `latest(name)`                            | последний отсчёт сигнала или `undefined`                                                        |
| `history(name, { withinMs })`             | отсчёты за последние `withinMs` (по умолчанию вся история), от старых к новым                    |
| `blinks(withinMs)`                        | число морганий за окно: фронты `detected: false → true` в истории `blink`                       |
| `poseChange(withinMs)`                    | `{ yaw, pitch }`: на сколько сдвинулась поза за окно (последний отсчёт минус первый)            |
| `average(name, field, withinMs)`          | среднее числового поля (`pulse.bpm`, `breathing.rate`, `pose.yaw`, …) за окно или `undefined`   |

Хелперы только ускоряют типовые случаи, всё то же самое можно посчитать по `history`. История хранит не больше
60 секунд и 2000 отсчётов на сигнал.

Опции `onSignal(name, handler, { minIntervalMs })` ограничивают частоту вызовов (для `pose` по умолчанию без ограничений).

## Одна камера, несколько потребителей

Камера одна: её держат разные владельцы (always-плагины для активной вкладки, вопрос `ctx.ask`, проверка Spectra), и сессия с сервером
у них общая. Чтобы плагин с `@camera always` не менял поведение остальных, действуют правила:

1. **Сигналы принадлежат владельцу always.** Камеру для always-плагинов держит один владелец (`ALWAYS_OWNER`), пока
   активная вкладка подходит под `@match` включённого плагина с `@camera always` и не на паузе. Набор сигналов
   плагинов (`start.signals`) подставляется только в сессию, которую держит он. Вопрос или проверка, открывшие камеру сами, получают сессию без сигналов (только жесты и
   эмоции), даже если установлен плагин с `@signals pulse`.
2. **Перезапуск не ломает чужое.** Смена набора сигналов перезапускает камеру, но не пока открыт вопрос или идёт
   проверка: перезапуск ждёт, пока они закончатся.
3. **Проверка Spectra видит только эмоции.** Её журнал содержит выражения лица (и готовность, подсказки, ошибки),
   а жесты, сигналы и остальную часть сырого ответа SDK (`blinking`, `talking`, пульс) нет. Пока проверка не идёт,
   журнал молчит, кроме отказов камеры и сервера.
4. **Известное ограничение:** отказ общей сессии (камера занята, сервер упал) снимает всех владельцев сразу.

## Согласие и данные

- Пульс и дыхание физиологические данные. Они доходят до плагина только если плагин объявил их в `@signals`, а
  пользователь установил его, увидев список в окне установки.
- Плагин работает в странице и может отправить данные дальше сам, как любой скрипт страницы. Это надо писать в окне
  установки и в разделе Consent and Data Handling поста: ставьте только плагины, которым доверяете.
- Расширение и сервер ничего не сохраняют.

### Права плагина

`@signals` и `@gestures` работают как `@grant` в Tampermonkey: что не объявлено, то плагину не приходит. Расширение
перед рантаймом плагина записывает в его мир (отдельный user script world) его объявленные списки, а рантайм:

- отбрасывает сигналы вне `@signals`: они не попадают ни в `onSignal`, ни в `ctx.signals` (`latest`, `history`,
  `blinks`, `poseChange`, `average` для необъявленного дают пусто, 0 или `undefined`);
- не вызывает `onGesture` и `ctx.onGesture` для жеста вне `@gestures`;
- один раз за страницу и сигнал или жест пишет `console.warn` («signal "pulse" is not declared in @signals, so this
  plugin does not get it»). То же при регистрации `onSignal`/`onGesture` и при `ctx.ask({ expect })` с необъявленным
  жестом; сам `ask` (ответ мышью, timeout) работает как раньше.

Без списка в конфигурации (тесты, ручной запуск) фильтра нет.

**Это не граница безопасности.** Плагин это произвольный JS на странице: он может сам слушать `window` и прочитать
`pleiades:signal` в обход рантайма (у `@grant` в Tampermonkey так же: недоступное API просто отсутствует в
`GM_*`, но скрипт на странице остаётся скриптом). Граница доверия другая: пользователь ставит только доверенные
плагины, окно установки показывает заявленное, а расширение не доставляет на страницу сигналы и жесты, которых не
объявил ни один плагин этой страницы. Рантаймовый фильтр защищает от ошибок и случайного чтения чужого (плагин, объявивший
`blink`, не увидит пульс, который запросил соседний плагин), но не от злонамеренного плагина.
