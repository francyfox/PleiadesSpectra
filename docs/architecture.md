# Архитектура: «Tampermonkey для лица» — плагины-реакции на жесты

Идея 22 из `docs/idea.md`. Редакция от 2026-11-19. Без PleiadesOrchestra и без своего агента.

SmartSpectra SDK превращается в набор жестов и реакций лица. Поведение задают **плагины**: по одному файлу на плагин,
API цепочкой в стиле Elysia. Плагины пишет человек или любой агент (Claude, ChatGPT) по файлу типов; в расширении —
список плагинов и установка загрузкой файла. Камера по умолчанию включается **только по событию** (появилась модалка
оценки) и выключается после ответа; камера для always-плагинов (жесты вроде скролла) работает, пока открыта и активна страница, на которой плагин установлен.

## Поток данных

```
Страница ── событие (появилась .rating-modal) ──▶ плагин (userScripts, USER_SCRIPT world)
                                                     │ ctx.ask(...)
                                                     ▼
                         content script ⇄ background ⇄ камера (Chrome: offscreen; Firefox: вкладка расширения)
                                                     │ кадры WS (localhost)        ▲ события жестов
                                                     ▼                             │
                                     apps/server: SmartSpectra SDK + распознавание жестов
```

## Части

| Часть            | Где                                | Что делает                                                                         |
| ---------------- | ---------------------------------- | ---------------------------------------------------------------------------------- |
| Runtime плагинов | `packages/reactions` (новый)       | API цепочкой, типы `.d.ts`, парсер заголовка; собирается в один JS для userScripts |
| Расширение       | `apps/wxt` (WXT, Alpine CSP + TSX) | список и установка плагинов, согласие, камера, оверлей (`ask`, `toast`)            |
| Сервер           | `apps/server` (Bun, Elysia)        | сессия SDK (`#lib/spectra-sdk`), жесты, WS для кадров и событий                    |

## Плагин: один файл

```js
// ==Reaction==
// @name        Оценка сервиса
// @match       *://shop.example.com/*
// @camera      on-demand
// @gestures    smile, confused, nod
// ==/Reaction==

reaction("rating").onVisible(".rating-modal", async (ctx) => {
	const answer = await ctx.ask("Как вам сервис?", {
		expect: ["smile", "confused"],
		timeoutMs: 8000,
	});
	if (answer === "smile") document.querySelector("#rate-5")?.click();
	if (answer === "confused") document.querySelector("#rate-2")?.click();
});
```

```js
// ==Reaction==
// @name        Скролл наклоном
// @match       *://*/*
// @camera      always
// @gestures    tilt-down, tilt-up
// ==/Reaction==

reaction("scroll")
	.cooldown(400)
	.onGesture("tilt-down", () => scrollBy({ top: 400, behavior: "smooth" }))
	.onGesture("tilt-up", () => scrollBy({ top: -400, behavior: "smooth" }));
```

- **Заголовок** — то, что расширение читает **без выполнения кода**: имя, сайты (`@match` → `matches` в
  `userScripts.register`), режим камеры, какие сигналы нужны (по ним — согласие).
- **Цепочка** — поведение. Как в Elysia: каждый метод возвращает экземпляр и накапливает типы.
  - Триггеры: `.onVisible(selector, h)`, `.onEvent(target, type, h)`, `.onGesture(gesture, h)` (только при `@camera always`).
  - Модификаторы: `.cooldown(ms)`, `.minConfidence(n)`.
  - Композиция: `.use(otherReaction)` — как `.use()` в Elysia, для общих кусков внутри файла.
- **`ctx`**: `ask(question, { expect, timeoutMs, position, size })` → жест или `"timeout"` (включает камеру на время вопроса,
  показывает оверлей); `toast(text)`; `event` (`{ gesture, confidence, expression }`) для `onGesture`.
- Жесты: `nod`, `shake`, `tilt-down`, `tilt-up` (по точкам лица, считаем сами), `smile`, `confused` (по `expression`),
  `talking` (по `talking`). Взгляда нет, подмигивание — позже и только по точкам век.
- Файл — **обычный JS**, без импортов: `reaction` — глобальная функция из runtime. Для агента и редактора —
  `reactions.d.ts` и `// @ts-check`. TypeScript-файлы — позже (транспиляция в расширении, например sucrase).

## Расширение

1. **Список плагинов** (страница расширения): имя, сайты, режим камеры, сигналы, вкл/выкл, удалить, посмотреть код.
2. **Установка загрузкой файла** (`<input type=file multiple>` и перетаскивание): расширение разбирает заголовок,
   показывает код, сайты и что плагин может включать камеру → «Установить». Без валидного заголовка — отказ.
   Хранение: `storage.local` (код + разобранный заголовок).
3. **Регистрация**: `userScripts.register({ id, matches, js: [{ code: runtime }, { code: plugin }], world: "USER_SCRIPT" })`.
   Runtime и плагин в одном мире; плагины разных файлов изолированы `worldId`.
   - Chrome: пользователь один раз включает «Allow User Scripts» на `chrome://extensions` (Chrome 138+).
   - Firefox: `userScripts` — optional-разрешение, кнопка «Разрешить скрипты» → `permissions.request()`;
     после обновления расширения скрипты стираются — перерегистрировать в `runtime.onInstalled`.
4. **Связь плагина с расширением**: `userScripts.configureWorld({ messaging: true })`, плагин шлёт
   `runtime.sendMessage` (`ask`, `toast`), события жестов приходят через content script (`CustomEvent` на `window`).
5. **Оверлей** (content script, shadow root, Alpine): вопрос `ask`, индикатор «камера включена — плагин „Оценка сервиса“»,
   запасные кнопки (ответить мышью), «Выключить».

## Камера

- **По событию (по умолчанию).** `ctx.ask()` → background включает камеру → кадры на сервер → ждёт жест из `expect`
  или таймаут → камера выключается. Каждое включение видно в оверлее.
- **Камера always-плагина** — держится, пока активная вкладка последнего сфокусированного окна подходит под `@match` включённого плагина с `@camera always` и не поставлена на паузу. Фоновая вкладка или чужой сайт в фокусе камеру не держат. Знак для пользователя: Бета стоит в углу с красной точкой, клик по точке или «Turn off camera» в попапе ставит вкладку на паузу до перезагрузки, смены адреса или закрытия.
- Где живёт захват:
  - Chrome — offscreen-документ (`USER_MEDIA`); разрешение камеры один раз на странице расширения.
  - Firefox — offscreen нет: вкладка расширения «Камера» (или sidebar, проверить); в фоне без нового запроса — проверить.
- Кадры ~640×480, 30 кадров/с (SDK требует ≥25), RGBA по WS на `localhost:3001` (~37 МБ/с; позже — сжатие), на сервере только в памяти.

## Сервер

- **SDK — обязательно в Worker** (`new Worker(...)` в Bun), не в главном потоке Elysia. Причины (замер 2026-11-19):
  `start()` блокирует поток JS ~2 с, а кадры идут 30/с по ~1,2 МБ — главный поток должен только принимать WS и
  отвечать расширению. Главный поток ⇄ Worker: `postMessage` с кадрами как transferable `ArrayBuffer` (без копии),
  обратно — события жестов, статус, ошибки. Распознавание жестов — в том же Worker, рядом с метриками.
  Проверить первым: грузится ли koffi (нативная часть SDK) в Bun Worker; запасной путь — отдельный процесс
  (`Bun.spawn` + IPC) с тем же протоколом сообщений.
- Одна сессия SDK на процесс (и на Worker), `faceMetrics`, телеметрия выключена, ключ в `apps/server/.env.local`.
- Калибровка нейтральной позы в начале каждого включения; жесты с порогом уверенности; в расширение — только события.
- Камера по событию = `start()` при включении и `stopAsync()` при выключении. Пауза в кадрах без `stop()` ломает
  сессию (`kTimestampGap` на каждом кадре), проверено 2026-11-19.
- Прогрев по замеру: `start()` ~2 с (блокирует поток JS сервера) + ~1,2 с от первого кадра до выражения ≈ 3–4 с
  до готовности `ask()`. Кадры не реже 25/с (иначе `kSustainedLowFrameRate`).
- `sendFrame` бросает исключение при ошибке — `#lib/spectra-sdk` его ловит, ставит `session.failed` и возвращает
  `false`; Worker закрывает сессию и создаёт новую при следующем включении камеры.

## Запуск

- `bun install`, ключ в `apps/server/.env.local`, `bun run dev`.
- Chrome: загрузить `apps/wxt/.output/chrome-mv3`, включить «Allow User Scripts».
  Firefox: `bun run build:firefox` в `apps/wxt`, загрузить временное дополнение, разрешить скрипты.
- Установить плагины из `examples/` загрузкой файлов.
- Linux: SDK требует glibc ≥ 2.35.

## Риски и что проверить первым

1. **Прогрев** при включении по событию ≈ 3–4 с (замер выше): в оверлее «смотрю…» и кнопки мышью; таймаут `ask`
   считать с готовности. Чтобы сократить — `.prepare(selector)`: стартовать SDK заранее, когда страница/элемент
   предвещает модалку. Блокирующий `start()` — возможно, вынести SDK в Worker.
2. Кивок, покачивание и наклон по 478 точкам (раскладка не документирована), шум `expression`.
3. `userScripts` + messaging + `CustomEvent` между мирами — собрать минимальный пример в Chrome и Firefox.
4. Firefox: камера без offscreen.
5. **Пересечения:** скролл головой — Glimra (#68), моргание-команды — OnBlink (#43), Hear Me (#92). Отличие —
   программируемые реакции, которые пишет агент, и камера по событию.

## Consent and Data Handling (тезисы для поста)

- Камера включена только пока плагин спрашивает, либо пока открыта и активна страница, на которой работает установленный пользователем always-плагин. Установка плагина с `@camera always` — согласие; окно установки и карточка плагина говорят это прямо. Пока камера работает, на странице стоит Бета с красной точкой и именем плагина; пауза в один клик (по точке или кнопкой в попапе).
- Каждое включение видно в оверлее с именем плагина; ответить можно и мышью.
- Плагин перед установкой показывает код, сайты и какие сигналы использует; вкл/выкл и удаление в один клик.
- Видео идёт только на `localhost`, обрабатывается в памяти, не сохраняется. Плагины получают жесты (`smile`,
  `nod`) и измерения (`blink`, `pose`, `expression`, `pulse`, `breathing`), без видео и точек лица.
- Измерения плагин получает только если объявил их в `@signals`; окно установки показывает их списком, для
  `pulse` и `breathing` с пометкой «не медицинские показания». В набор сессии сервера входят только запрошенные
  сигналы: без `@signals pulse` метрики `cardio` и `breathing` SDK не включаются (`docs/signals.md`).
- Плагин работает в странице и может передать полученное дальше, как любой скрипт страницы: поэтому ставить стоит
  только плагины, которым доверяешь; расширение и сервер сами ничего не отправляют и не сохраняют.
- Телеметрия SDK по умолчанию выключена (`SMARTSPECTRA_TELEMETRY` в `.env` сервера, включается только явно).
  SDK всё равно обращается к SmartSpectra для проверки API-ключа. Без медицинских выводов: пульс и дыхание это
  оценки по видео, плагины не должны ставить диагнозы; `blink` пока не проверен на реальных морганиях.
