## Правила конкурса (кратко)

- Работающее приложение, использующее минимум один живой сигнал SmartSpectra.
- Нужны: пост на DEV (на английском, иначе нет приза), публичный репозиторий с инструкцией запуска, демо-видео.
- Обязателен раздел Consent and Data Handling: как получаем согласие на камеру, как хранятся, передаются и удаляются данные.
- Запрещены: диагностика и лечение, медицинские решения, скрытое или несогласованное наблюдение.
- Один участник, без команд. Критерии жюри: использование технологии, UX, оригинальность.

### Проверено по документации (2026-11-18)

- Группы метрик: `cardio` (пульс, HRV), `breathing`, `face`, `eda` (EDA Proxy, первый результат после ~35 с).
- `face`: `blinking`, `talking` (оба `detected`), `landmarks` (точки x/y), `expression` (оценки 0–100%:
  ANGRY, CONTEMPT, DISGUST, FEAR, HAPPY, NEUTRAL, SAD, SURPRISE).
- Нет: взгляда (gaze), радужки, позы головы. Любая оценка взгляда считается самостоятельно по landmarks. Движение головы так считает Glimra (#68): landmarks против позы покоя, `src/main/presageHeadMotion.cjs`, Electron-воркер `presageNativeWorker.cjs` (github.com/0xaje/Glimra).
- Браузерного SDK нет (2026-11-19): только C++, Swift, Kotlin, Node/TS. Но Node умеет принимать кадры извне: `useCustomInput()` → `start()` → `sendFrame(buffer, width, height, stride, pixelFormat, timestampUs)`, а также `useFile()`. Значит, SDK может работать на сервере, получающем видео из браузера. Для Electron есть renderer SDK с `useMediaStream()`. Docker/glibc/Bun в документации не описаны.
- Landmarks в Node: `faceMetrics`, `metrics.face?.landmarks?.at(-1)?.value`. Число точек, раскладка и частота не документированы — проверять живым запуском.
- Цен по метрикам в документации нет.
- По коду Glimra (не документация, 2026-11-19): `@smartspectra/node-sdk` ^3.4.0, landmarks — 478 точек (как MediaPipe Face Mesh с радужкой, раскладку проверять), координаты в пикселях камеры; есть `stable`/`reset`; опции `enableTelemetry: false`, `enableAccumulatedOutput: false`; валидация `kMultipleFacesFound`/`kNoFaceFound`; Linux нужен glibc 2.35+. В их живом тесте `blinking` не дал ни одного моргания — моргание ненадёжно, проверять.
- `breathing` (2026-11-19): `rate` + `upper_trace` (грудь) и `lower_trace` (живот) — волна движения, без своей confidence, `stable` от rate (≥45). Задержка не документирована. Других датчиков, кроме видео, у SDK нет.
- Пульс (2026-11-24, записанные ролики 640×480 через `apps/server/scripts/send-video.ts`, один человек, `PULSE_RATE` + лицо): окно 12 с по документации; первый замер ~10–13 с после `ready`, дальше ~1,6 замера/с. Подсказка `kChestNotVisible` (7) приходит не по пикселям груди: с чёрным квадратом на груди пульс идёт (97 уд/мин, 41 замер). По опытам она зависит от размера лица в кадре: голова ~40% высоты кадра — подсказка весь ролик и 0 замеров за 90 с; ~29% — пульс. Уменьшение того же близкого ролика до 70% и 55% с чёрными полями даёт пульс на ~13 с (88 и 86 уд/мин). Это вывод по трём роликам, в документации этого нет (там грудь нужна только дыханию). Точность по эталону (часы, пульсометр) не сверена: `confidence` ~100 — не точность.
- Дыхание (2026-11-24) убрано из продукта: окно 30 с, камера должна быть неподвижной, замеры почти всегда `confidence: 0`. Пинвил остаётся индикатором ожидания замера пульса.
- Живой замер (2026-11-19, Bun, `useCamera` 640×480, `faceMetrics`): холодный старт до `kStarting` ~1–2 с; `talking`/`blinking` через ~3 с после старта; `kRunning`, первые `landmarks` (478 точек, `stable`) и `expression` — через ~4,5 с после `kStarting`, ~6 с после `start()`. Повторный `start()` после `stop()` быстрее не стал (~6 с до expression): это прогрев по кадрам, а не загрузка. ~35 пакетов метрик/с. `stopAsync()` 0,06 с, но шлёт `error` kInvalidState (1) — похоже безвредно.
- Замер с `useCustomInput` + `sendFrame` (2026-11-19, RGBA 640×480 через ffmpeg, как в продукте): `start()` → `kStarting` ~1,7 с; `kRunning` сразу с первым кадром; `landmarks` через ~0,07 с, `expression` через ~1,2 с после первого кадра. Прошлые ~6 с — подстройка камеры в `useCamera` (она же переводит камеру в ручную экспозицию и оставляет её тёмной).
- Нужно ≥25 кадров/с: на 15 — `kFrameRateTooLow` через ~5 с, затем `kSustainedLowFrameRate` и `kError`. На 30 кадрах/с ~29 пакетов метрик/с.
- Пауза в кадрах без `stop()` не работает: после 10 с паузы каждый `sendFrame` бросает `kTimestampGap` («gap between camera frame timestamps»), статус не становится `kError`, сам не восстанавливается. Рабочий путь: `stopAsync()` (~0,01 с) при выключении камеры и `start()` при включении (~2 с до `kStarting`, блокирует поток JS) + ~1,2 с до выражения.
- `sendFrame` при ошибке бросает исключение, а не возвращает `false`.
- Amplitude/apnea/baseline и подобное дыхательное в SDK недоступны, их запрос роняет `start()`.

## Как работать с идеями

- Все обсуждаемые идеи записывать в `docs/idea.md` (суть, связь с Pleiades, пересечения с реестром, критика, статус).
  Писать кратко: одна-две строки на идею (суть, статус, главный риск), без подробных разделов.
  Новую идею дописывать в конец, при смене статуса обновлять существующую запись.

- **Критиковать идеи.** Не поддакивать. Для каждой идеи называть слабые места: пересечение с реестром,
  точность сигналов, нарушение правил конкурса (медицина, скрытое наблюдение), нагрузку на срок до дедлайна,
  размытое использование SDK.
- Если идея опирается на сигнал, которого в SDK нет, прямо говорить об этом.
- Рекомендовать один вариант, а не перечислять всё подряд.
- Артефакты на claude.ai не публиковать; документы класть в `docs/` в виде markdown.


## Писать код человекочитаемым

Использовать комментарии только для jsdoc, декомпозировать в маленькие функции, отдавать предпочтение composition стилю больше чем ООП. Использовать понятные имена функций и переменных, сокращать можно в редких случаях например в цикле foo.map((i) => i.trim()) в данном случае происходит быстрая однострочная трансфорамацияи нет смысла помнить что за переменная i. Писать модуль в angular like стиле foo/foo.ts главный файл импортов, foo.service.ts сервисы, foo.utils.ts утилиты, foo.controller.ts контролер, при необходимости можно добавить модель.
